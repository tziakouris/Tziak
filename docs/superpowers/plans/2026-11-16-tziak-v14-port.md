## Global Constraints

- Test package id `com.tziak.music.next`, app label "Tziak Next"; release version `14.0.0-tziak.1`, versionCode `155` (above v14's 154).
- Owner email must appear nowhere (code, README, commits, APK). Commit identity: `Andreas Tziakouris <noreply@tziak.invalid>` (already set in repo config). Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- No `git push`, no GitHub release. Signing key and passwords stay in `~/.tziak` (`signing.env`, `release.keystore`), never in the repo.
- Keep GPL-3.0 and upstream credit to Metrolist. Keep Metrolist's About links as credit.
- Never add a process-kill/restart feature. Do not change playlist song order inside playlists.
- Build command: `./gradlew :androidApp:assembleRelease` (run from the worktree root; find the exact task with `./gradlew :androidApp:tasks --all | grep -i assemble` first).

## Review Focus

1. Android Auto with zero playlists or a playlist with 500+ songs: shows an empty list / loads, never crashes.
2. Service start refused by Android (`ForegroundServiceStartNotAllowedException`): service keeps running, browsing and play still work.
3. "Keep debug log" switched off then on again, and off while a crash happens: no stale file, no exception.
4. Updater given a release with no `.apk` asset, a malformed tag, or no network: no update shown, no crash; `14.0.0-tziak.2` > `14.0.0-tziak.1`.
5. Removing downloads (one and all) while a download is running: list updates, no crash.
